01

Criminal Records Dashboard

crd.scilaw.org

SciLaw/Full-stack build · data pipeline · analytics

An interactive analytics platform for criminal-justice research, turning tens of millions of raw court records from seven U.S. jurisdictions into a queryable dashboard on recidivism, dispositions, and offense patterns.

  • Data pipeline that ingests, de-duplicates, and resolves individuals across jurisdictions, then classifies offenses using statute maps with an LLM fallback (Amazon Bedrock) for residual cases.
  • Serverless architecture on AWS — Athena over partitioned data, Lambda query services, Cognito authentication with server-side tiered access, and CloudFront/WAF.
  • Recidivism analytics built on explicit criminal-event definitions: reoffense rates, survival curves, transition matrices, and offense-to-offense flows.
  • Natural-language query that translates plain-English questions into structured filters and chart navigation.
  • Privacy by design — access tiers enforced server-side, scoped IAM, and no raw-row exports at any tier.

SciLaw

scilaw.org

Web redesign · content strategy · front-end build

A redesign of the Criminal Records Database landing page, so that visitors can immediately see which data projects are live and explorable and which are still in development.

  • Foregrounded active projects. Restructured the page around a clear distinction between live datasets and upcoming ones. Active projects are visually prominent and clickable, and in-progress ones have a distinct “coming soon” treatment.

  • Messaging and UX copy. Rewrote headings, calls-to-action, and value-proposition text for specific audiences. Removed redundant links so each section has one clear next step.
  • Technical communication. Translated the database’s data-normalization approach into plain language for non-technical researchers and decision-makers.
  • Safe, repeatable editing. Developed a scripted workflow for making and verifying changes to a complex page-builder layout without breaking it.

04

Poker Night

Case study

College event/Pipeline design · direction · editing

A data-driven broadcast-overlay pipeline for live-event video. I produced two edited poker videos (~30 min total) for a screening, with TV-style graphics generated automatically from a structured hand log.

  • Overlay engine in Python and Pillow, built as a state machine that computes display state in source time and samples it once per output frame (29.97 fps) — frame-accurate cards, per-street bets, pot and running profit, with opponent cards never revealed early. Frame reuse keeps a 15-minute video to ~400 unique overlay images.
  • Speech-to-text indexing with Whisper (turbo, int8 via sherpa-onnx) and Silero VAD to locate key moments — "I fold", "All in" — across ~4 hours of audio, plus RMS energy profiling to time each caption to the spoken word.
  • Compositing and edit in FFmpeg: overlay filtering, concatenation without re-encoding, freeze-frame inserts, and 40 ms audio fades over cuts; segment-based rendering to stay under a 3-minute-per-job compute limit.
  • Single source of truth — a shared hand-log web app (cards, bets, streets, stack checks) whose validation flags chip stacks that don't reconcile.
Python Pillow FFmpeg Whisper Silero VAD sherpa-onnx
